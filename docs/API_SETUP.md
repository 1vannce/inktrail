# Connect the external tracker API

PanelPaw reads catalog data from Kitsu. Your reading entries and custom lists live in a separate external REST service. The app has no backend server, database, or local entry store. Use an account-owned MockAPI project for persistent CRUD storage. The adapter also supports the old Beeceptor contract while you migrate.

## Migration status and required configuration

The existing local `.env` still selects the historical public Beeceptor demo. It has been left unchanged to preserve local configuration. No replacement MockAPI endpoint has been provisioned or live-tested. The required value is:

```dotenv
# Paste the actual HTTPS project base URL from your MockAPI dashboard.
# Include its prefix (such as /api/v1); exclude /entries and /lists.
EXPO_PUBLIC_TRACKER_API_URL=
```

The original demo was created on **October 11, 2026**. Beeceptor documents removal of unclaimed endpoints after 30 days, so plan to finish migration **before November 10, 2026**. This is an estimated cleanup date, not a live confirmation of claim status or deletion time. [Retention policy](https://beeceptor.com/pricing/) checked October 28, 2026.

The app now ignores that specific historical demo URL as an automatic build default. A previously saved connection is preserved and shows a migration notice on the Connection screen. No data is moved or deleted automatically. A new installation with only the old environment URL can browse the catalog, but must connect a tracker before saving.

## Recommended for your own tracker: MockAPI

MockAPI requires an account and one-time resource configuration. Choose a plan that supports one project with two resources, `entries` and `lists`; check the current [plan details](https://mockapi.io/) in your dashboard. Account ownership avoids relying on an anonymous Beeceptor endpoint's retention window, but does not guarantee indefinite storage or production security. Keep your own backup.

1. Sign in at [MockAPI](https://mockapi.io/) and create a project named `PanelPaw`.
2. Create two top-level resources named exactly `entries` and `lists`. Do not nest one under the other.
3. Use the fields below. Keep the generated `id` field. Start both resources empty; random generated data will not match the app's model.
4. Copy the project's HTTPS base URL from the dashboard. Include any configured prefix such as `/api/v1`, but exclude `/entries` and `/lists`.
5. Open PanelPaw's **Connection** screen, paste that base URL, then connect. The app checks both collection endpoints before saving the connection.

The provider creates standard REST routes for each resource and accepts JSON requests. [Official MockAPI setup guide](https://github.com/mockapi-io/docs/wiki/Quick-start-guide).

### Resource: `entries`

| Field | JSON type | Meaning |
| --- | --- | --- |
| `id` | string | Generated by the provider; omit when creating. |
| `mangaId` | number | Numeric Kitsu manga catalog ID. |
| `title` | string | Display title saved from the catalog. |
| `imageUrl` | string | Cover URL; empty string is allowed. |
| `format` | string | Catalog format, such as `Manga` or `Manhwa`. |
| `totalChapters` | number or null | Known total, or `null` when the catalog has no total. |
| `status` | string | `reading`, `planned`, `completed`, `on_hold`, or `dropped`. |
| `progress` | number | Whole chapters read, starting at zero. |
| `listId` | string or null | A custom list's ID, or `null` for no custom list. |
| `createdAt` | string | ISO date/time set when saved. |
| `updatedAt` | string | ISO date/time set when changed. |

Choose Number for numeric fields and String for text fields in the schema editor. Preserve JSON `null` for unknown `totalChapters` and unassigned `listId`; do not use the string `"null"`. The app sends all business fields, so Faker generators are unnecessary.

### Resource: `lists`

| Field | JSON type | Meaning |
| --- | --- | --- |
| `id` | string | Generated by the provider. |
| `name` | string | Custom reading-list name. |
| `createdAt` | string | ISO date/time set when created. |

`src/api/tracker.js` validates both models at runtime; `src/types.js` defines the allowed reading statuses. The app expects each collection response to be a raw JSON array (`[]` when empty), and each successful create/update response to be a JSON object containing its `id`.

## Migrate the existing library

Changing the URL selects a different library; it does **not** transfer records. Complete these steps before the old service expires:

1. Pause edits on all clients using the old endpoint. Save the raw JSON from GET `/entries` and GET `/lists` as separate backup files outside the repository. Keep both even if one is empty. Check for successful HTTP responses and JSON arrays; an error response is not a backup. The historical source base URL is `https://ca491042a4a2e9cd0092.free.beeceptor.com`. If it has expired, recover from a previous backup; the app has no durable local copy.
2. Create the empty MockAPI resources using the schemas above. Leave response templates at their standard shapes: arrays for collection GETs and objects for POST/PUT. Do not generate random records.
3. Recreate each list with POST `/lists`, sending its `name` and original `createdAt`, **without its old `id`**. Record a mapping of each old list ID to the new string ID returned by MockAPI.
4. Recreate each entry with POST `/entries`, omitting its old `id`. Keep all other fields and timestamps, but replace a non-null `listId` using the mapping from step 3. Preserve actual JSON numbers and `null`. If a referenced list is missing from the backup, resolve it explicitly before importing; do not silently discard its membership.
5. Read both destination collections back. Compare counts and every business field with the backup, accounting for new record IDs and mapped list IDs. Confirm no duplicated `mangaId`, and every non-null `listId` points to an imported list. If a write times out, inspect the destination before retrying: blindly repeating POST can create duplicates. Keep the backup and old service untouched if import is incomplete.
6. Set the new base URL locally and in the deployment environment as described below. Rebuild/redeploy, then switch each existing client through **Connection**. Select **Use configured default URL**, then **Test & connect**, or paste the URL manually. Selecting the default only fills the input; the app saves it after both collection checks pass.
7. Reload and confirm the migrated titles, progress, statuses, and list memberships. Use a separate disposable title/list to perform the CRUD checks under **Manual verification**, including null chapter totals and unfiled entries. Only remove those disposable records after testing. Retain the backup after cutover.

If you deliberately want an empty tracker, still export the old collections first, then skip importing. For rollback while Beeceptor remains available, paste the old URL and **Test & connect**; changes made on MockAPI will not appear there. Avoid writing to both trackers after cutover.

Beeceptor's public free tier currently allows 50 requests per endpoint per day and ten small CRUD objects; old records can be removed when full. A backup can only preserve records still present. [Plan limits](https://beeceptor.com/pricing/) and [storage behavior](https://beeceptor.com/docs/crud-api/).

## Configure the app

### In the app

Open **Connection**, paste the base URL, and connect. Only the URL preference is persisted using AsyncStorage. A configured external service stores the actual entries and lists. A connection test verifies readable collections, while the first save verifies the provider accepts writes.

### Through an environment file

From the `panelpaw` directory in PowerShell:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Edit `.env`:

```dotenv
EXPO_PUBLIC_TRACKER_API_URL=https://YOUR_PROJECT.mockapi.io/api/v1
```

Replace the entire example URL with the one from your dashboard. The literal `YOUR_PROJECT` URL is rejected; the blank `.env.example` setting is intentional. Edit only `EXPO_PUBLIC_TRACKER_API_URL` in an existing `.env`; do not replace the file or any other credentials. Stop the running Expo process and restart with a cleared Metro cache after changing the environment, so transformed environment values are refreshed:

```powershell
npx expo start --clear
```

For Vercel, set `EXPO_PUBLIC_TRACKER_API_URL` to the same base URL in the intended deployment environment, then create a new deployment. Changing a hosted environment variable alone does not update an already-built Expo bundle. Local `.env` files are excluded from Git and CLI uploads.

Saved device/browser preferences take precedence over the build setting, including an empty value saved by **Disconnect**. Existing users must select the new default or paste the URL and connect; the app does not silently switch their library. A malformed default reports a configuration error without replacing a valid saved connection.

`EXPO_PUBLIC_` values are included in the client bundle. They are configuration, not secret storage. Supply only the public API base URL, never a dashboard URL, private API key, password, access token, query string, or URL with embedded credentials. No MockAPI account credentials are needed by this app.

## REST contract

All paths are relative to the configured base URL. Request bodies use `Content-Type: application/json`.

| Action | Method | Path | Body |
| --- | --- | --- | --- |
| Read library | GET | `/entries` | None |
| Read current entry before an edit | GET | `/entries/:id` | None |
| Save title | POST | `/entries` | Complete entry without `id` |
| Update chapters, status, or custom list | PUT | `/entries/:id` | Complete updated entry |
| Remove saved title | DELETE | `/entries/:id` | None |
| Read custom lists | GET | `/lists` | None |
| Verify a selected custom list | GET | `/lists/:id` | None |
| Create custom list | POST | `/lists` | `{ "name": "Weekend reads", "createdAt": "..." }` |
| Rename custom list | PUT | `/lists/:id` | Complete updated list |
| Delete custom list | DELETE | `/lists/:id` | None |

Updates send the complete record because some providers replace the entire resource on PUT. A successful DELETE may return JSON or an empty body.

Illustrative entry create body (replace the sample title and `mangaId` with the actual Kitsu record being saved):

```json
{
  "mangaId": 2,
  "title": "Example manga",
  "imageUrl": "",
  "format": "Manga",
  "totalChapters": null,
  "status": "reading",
  "progress": 12,
  "listId": null,
  "createdAt": "2026-10-11T10:00:00.000Z",
  "updatedAt": "2026-10-11T10:00:00.000Z"
}
```

The provider adds `id`. To update this record, send its complete fields with the changed `progress`, `status`, or `listId` to `/entries/{id}`. The app refreshes affected query data after the server confirms a write.

Deleting a custom list first updates its entries to set `listId: null`, then deletes the list. Titles stay in the library. This involves multiple REST requests and is not a server transaction. If a request fails, some entries may already be detached; refresh and retry after the service recovers. Use an external transactional backend if atomic list deletion is required.

## Catalog configuration

The client reads the public [Kitsu JSON:API catalog](https://kitsu.docs.apiary.io/) at `https://kitsu.app/api/edge`. Catalog requests send **`Accept: application/vnd.api+json`**; using a plain JSON Accept header may return HTTP 406.

Example paths (brackets are shown unencoded for readability; the client uses `URLSearchParams` to encode them):

```text
GET /manga?filter[text]=solo&filter[subtype]=manhwa&page[limit]=12&page[offset]=0&include=categories
GET /manga?filter[subtype]=manga&sort=-userCount&page[limit]=12&page[offset]=0&include=categories
GET /manga/:id?include=categories
```

The **All** catalog merges separately requested manga and manhwa results, retaining an independent page cursor for each subtype and removing duplicate IDs. Discovery results are ordered by `userCount`; merged search results prioritize exact, prefix, and contained title matches, preserving provider order for ties and other results. Categories included in the JSON:API response provide genre labels for each related title.

The adapter maps numeric Kitsu IDs, titles, poster images, publication status, synopsis, and chapter totals into the app's `Manga` type. `averageRating` uses a 100-point scale and is converted to the displayed 10-point score. Unknown chapter totals remain `null`; author credits are optional and are not fetched by this adapter. The stored `mangaId` always identifies a Kitsu manga resource. Do not import IDs from another catalog into this tracker without explicitly mapping them.

Public catalog reads need no app API key. PanelPaw uses Kitsu only for catalog retrieval; all tracker writes go to the configured MockAPI or Beeceptor service. A shared queue spaces catalog requests about 1.05 seconds apart as a courtesy, and search is debounced. This pacing is an app choice, not a claimed Kitsu rate-limit allowance. Cancelled requests and temporary service failures are handled by the HTTP client. Retry after a displayed network or rate-limit error.

## Manual verification

Use a dedicated test endpoint and inspect its dashboard while you:

1. Connect and confirm GET `/entries` and GET `/lists` return arrays.
2. Search for a title and save it. Confirm POST `/entries` and the new server-assigned ID.
3. Change progress and status. Confirm PUT `/entries/:id`; reload the app and confirm those values return from GET `/entries`.
4. Create a custom list, rename it, and assign a saved title. Confirm POST/PUT `/lists` and PUT `/entries/:id`.
5. Delete the custom list. Confirm entry updates precede DELETE `/lists/:id`, and the title remains saved without a list.
6. Remove the title and reload. Confirm DELETE `/entries/:id` and that it remains absent.
7. Disable networking or use an invalid endpoint. Confirm a clear error is shown and no successful save is claimed.

## Troubleshooting and scope

- **Catalog works, library does not:** Kitsu and the tracker are separate services. Configure a writable tracker endpoint.
- **404 or non-JSON response:** Check the base URL and resource names. Do not paste a dashboard URL or append `/entries` to the base.
- **Connected but save fails:** Confirm POST/PUT/DELETE are enabled and check provider quota. The connection test only uses GET.
- **Records disappear on Beeceptor:** Check the shared ten-object limit and endpoint retention.
- **Unexpected generated records:** Clear only your own test resource data in the provider dashboard and start with empty collections.
- **Browser-only network error:** Ensure a replacement provider allows CORS for your web origin and the required methods and headers. Native apps do not enforce browser CORS.

These endpoints are public demonstrations, with one library per endpoint and no account isolation. Use a dedicated endpoint and non-sensitive test data. A production version should keep this frontend-to-REST architecture while moving authentication, user ownership, validation, uniqueness, and atomic operations into an external API service. Client validation helps the interface; it does not secure a public endpoint. Two clients can still create duplicates or overwrite each other's updates without server-side constraints.
